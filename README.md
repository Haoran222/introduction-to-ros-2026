# Introduction to ROS 2026 — Autonomous Driving

This repository contains a ROS 2 Jazzy autonomous-driving system running in a
Unity city simulation. The vehicle follows a recorded route, reacts to traffic
lights and NPC vehicles, performs emergency braking or basic obstacle
avoidance, and stops at the final goal.

The assignment specification is available in
[AutonomousDriving.pdf](AutonomousDriving.pdf). The ROS 2 workspace is located
under [`project/`](project/).

## Quick Start

The following commands assume that the terminal is in the repository root.
Install Git LFS and download the bundled Unity asset once after cloning:

```bash
git lfs install
git lfs pull
```

Build the project with:

```bash
cd project
source /opt/ros/jazzy/setup.bash

colcon build --symlink-install \
  --packages-select simulation perception planning decision_making control \
  autonomous_driving_bringup

source install/setup.bash
```

Open a new terminal in the repository root and start the complete system:

```bash
cd project
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 launch autonomous_driving_bringup autonomous_driving.launch.py
```

The launch file starts the Unity bridge, perception, planning,
decision-making, control, and the bundled Linux Unity player. Press `Ctrl+C`
in the launch terminal to stop the complete system.

Do not run `dummy_controller` together with the autonomous controller. Both
nodes publish commands to `/car_command`.

## System Architecture

```text
┌──────────────────────── Unity Simulation ────────────────────────┐
│ RGB / Depth / IMU / Pose / Twist              VehicleControl    │
└──────────────────┬────────────────────────────────▲──────────────┘
                   │ TCP                           │ UDP
                   ▼                               │
              simulation                    /car_command
                   │                               ▲
                   ├── sensor data and ego state   │
                   ▼                               │
              perception                          control
           ┌───────┴────────┐                      ▲
           │                │                      │
    traffic-light state  current point cloud       │
           │                │                      │
           ▼                ▼                      │
           └──────── decision_making ◄──── planning
                           │                ▲
                           └── safe path ────┘
```

The main processing pipeline is:

```text
Unity sensors
  -> traffic-light and obstacle perception
  -> local waypoint selection
  -> curvature-aware trajectory generation
  -> decision-state trajectory gating
  -> Pure Pursuit and speed PI control
  -> /car_command
  -> Unity vehicle
```

## ROS 2 Packages

### `autonomous_driving_bringup`

This package provides the main entry point for the project.

The
[`autonomous_driving.launch.py`](project/src/autonomous_driving_bringup/launch/autonomous_driving.launch.py)
file declares shared parameters, includes the package-level launch files,
starts Unity after the TCP receiver is ready, and shuts down the complete stack
when Unity exits.

Important launch arguments include:

- `start_unity`: start the bundled Unity player; default is `true`.
- `unity_start_delay`: delay before starting Unity; default is 2 seconds.
- `waypoints_file`: recorded route used by planning.
- `max_speed`: maximum planned speed.
- `max_lateral_accel`: lateral acceleration limit for cornering.
- `max_range`: maximum perception range.

To use an externally started Unity instance:

```bash
ros2 launch autonomous_driving_bringup autonomous_driving.launch.py \
  start_unity:=false
```

### `simulation`

This package handles communication between Unity and ROS 2.

- `unity_TCP_stream_receiver.cpp` receives Unity sensor packets and dispatches
  them to the appropriate parser.
- `true_state_parser.h` publishes the vehicle pose and twist.
- `rgb_camera_parser.h` and `depth_camera_parser.h` publish image data and
  camera information.
- `imu_parser.h` publishes IMU measurements.
- `ROS_command_transmitter.cpp` subscribes to `/car_command` and sends throttle,
  steering, and brake commands to Unity over UDP.
- `JSON_param_reader.cpp` reads the Unity network and sensor configuration.
- `simulation_config.json` contains the spawn point, NPC events, socket ports,
  and sensor settings.

NPC events are controlled by:

```json
"eventEnable": [
    true,
    true
]
```

NPC vehicles are activated when the ego vehicle enters their trigger regions.
They are not permanently visible at the beginning of the simulation.

### `perception`

This package provides sensor transforms, depth processing, and traffic-light
recognition.

- `sensor_tf_broadcaster_node.cpp` publishes static transforms between the
  vehicle and its sensors.
- `depth_to_pointcloud_node.cpp` projects `16UC1` depth images into a
  `PointCloud2` stream.
- `traffic_light_detector_node.cpp` uses HSV color thresholds, contour shape,
  and traffic-light housing geometry to classify signal lamps.

Traffic-light outputs are:

- `/traffic_light/state`: classification, confidence, and detected pixel area.
- `/traffic_light/must_stop`: stop request consumed by decision-making.
- `/traffic_light/debug_image`: RGB image with the selected detection box.

The default policy stops on red. Yellow is reported for diagnostics but does
not request a stop.

### `planning`

This package manages route progress and generates a local trajectory.

- `waypoint_recorder_node.cpp` records a route during manual driving.
- `goal_selector_node.cpp` maintains monotonic route progress and publishes a
  local waypoint window.
- `spline_utils.h` implements Catmull–Rom spline sampling, heading, and
  curvature calculations.
- `trajectory_planner_node.cpp` creates a velocity profile from curvature and
  longitudinal acceleration limits.
- `waypoints.yaml` contains the final route for the supplied Unity map.

Planning outputs include:

- `/planning/next_goal`
- `/planning/local_path`
- `/planning/trajectory`
- `/planning/trajectory_path`
- `/planning/goal_reached`

### `decision_making`

This package converts perception results into safe driving behavior.

- `forward_obstacle_monitor_node.cpp` projects the current depth point cloud
  onto the planned path and calculates obstacle distance, lateral offset,
  closing speed, and avoidance clearance.
- `decision_state_machine_node.cpp` gates the planned trajectory according to
  traffic lights, obstacles, and input freshness.

The state machine contains the following states:

| State | Behavior |
| --- | --- |
| `DRIVE` | Preserve the planned trajectory |
| `CAUTION` | Reduce speed according to obstacle distance |
| `TRAFFIC_STOP` | Set all trajectory velocities to zero |
| `EMERGENCY_STOP` | Immediately set all velocities to zero |
| `AVOIDING` | Reduce speed and shift the local trajectory laterally |
| `SENSOR_FAULT` | Apply a fail-safe stop when required inputs are stale |

### `control`

This package converts the safe trajectory into simulator commands.

- Lateral control selects a target by trajectory arc length and uses Pure
  Pursuit to calculate steering.
- Longitudinal control uses a PI speed controller to calculate throttle or
  brake.
- Stale input, an empty trajectory, or a requested zero-speed trajectory causes
  full fail-safe braking.

The final output is:

```text
/car_command
simulation/msg/VehicleControl
```

### `dummy_controller`

This is a small teaching example that publishes a fixed throttle and periodic
steering command. It is not part of the autonomous-driving pipeline and is only
used to test the Unity control interface.

1. `autonomous_driving_bringup/launch/autonomous_driving.launch.py`

## Debugging Commands

List active nodes and topics:

```bash
ros2 node list
ros2 topic list
```

Inspect the decision state:

```bash
ros2 topic echo /decision_making/state
```

Inspect traffic-light perception:

```bash
ros2 topic echo /traffic_light/state
ros2 topic echo /traffic_light/must_stop
```

Inspect the current forward hazard:

```bash
ros2 topic echo /decision_making/hazard_status
```

Display the traffic-light debug image:

```bash
ros2 run rqt_image_view rqt_image_view
```

Select `/traffic_light/debug_image` in the image-view window.

Check the vehicle-command frequency:

```bash
ros2 topic hz /car_command
```

## Recording a New Route

The final route is stored in
[`waypoints.yaml`](project/src/planning/config/waypoints.yaml). A new recording
is not required for the supplied map.

To record a route for a different map:

```bash
ros2 launch planning record_waypoints.launch.py \
  output_file:=/tmp/waypoints_recorded.yaml
```

Drive manually to the destination, press `Ctrl+C`, inspect the generated file,
and then copy it into the planning configuration directory.

## Validation Status

The final implementation completed two consecutive full-route simulations:

- A merging NPC triggered `EMERGENCY_STOP -> AVOIDING -> DRIVE` and was avoided
  without a collision.
- The corrected right-turn waypoints kept the vehicle clear of the guardrail
  and road divider.
- Red lights triggered `TRAFFIC_STOP`, followed by automatic resumption.
- The vehicle reached the final goal near `(-64.1, -14.3)` and held full brake.
- No Unity or ROS 2 process crashed during either validation run.

Unity occasionally produces a sensor or planner data gap of approximately
0.4–0.5 seconds. The state machine enters `SENSOR_FAULT`, applies full brake,
and automatically returns to normal operation when data resumes.
